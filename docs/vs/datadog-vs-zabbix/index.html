Read this before you price anything

Datadog has a free plan for up to 5 hosts, but it keeps metrics for one day only, against 15 months on Pro. That is not a like-for-like replacement for monitoring you rely on, so the comparison uses Pro even at 5 servers.

What Zabbix needs to run at 25 servers

Zabbix server, a database and the web frontend. Memory is fitted to Zabbix's own hardware table, which asks for 8 GB at 1,000 monitored metrics and 16 GB at 10,000, assuming about 100 metrics per server; beyond 100 servers this runs above Zabbix's own figures. Disk uses Zabbix's database formula at 90 bytes per value, 100 items per server refreshed every minute, 31 days of history and a year of trends: about 0.5 GB per server.

ResourceRequiredHow it is derived
Memory9.3 GB 5.7 GB for the stack at rest, plus 73 MB per monitored server, plus 25% headroom
Disk32.5 GB 20 GB base, plus 0.5 GB per server
vCPU2 The project's own baseline. For this workload memory runs out before the processor does.

What you give up, stated plainly

  • Uptime is now yours. Datadog has an operations team on call. Self-hosted, a failed upgrade at 18:00 on a Friday is your evening.
  • Backups only exist if you test restoring them. The $16.80 line above buys snapshots, not a rehearsed recovery.
  • Zabbix is a multi-container stack with a database you have to back up yourself. That is why the maintenance line is 1.5 hours a month rather than zero.
  • Licensing: Zabbix is AGPL-3.0. That only matters if you modify Zabbix itself and offer it to others over a network.
  • Feature parity is never exact. Zabbix covers the core of what teams use Datadog for; the long tail of integrations and enterprise controls is where the gap shows.
